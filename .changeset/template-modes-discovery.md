Mode discovery, per-mode timeouts and default harnesses:

- **`delegate_modes` tool** (read-only): lets the model list every mode with its permission tier on each harness (danger and unlisted native modes marked as needing a confirmed `allowDangerous`), whether it has a default task/scope or a host-run check, its default harnesses and timeout, and which harnesses are on `PATH`, without running anything. Project-local templates appear only in a trusted project. `verify:` commands, prompt bodies, default task/scope text and file paths are never shown. Template text goes through one shared sanitizer: ANSI, control, bidi, zero-width, private-use and other invisible characters (tag characters, variation selectors, Hangul fillers, the blank Braille pattern, U+034F, U+17B4/U+17B5) are stripped, combining-mark runs are cut to two, text is one line and length-capped, and it is quoted and labelled as data. Mode and model names show non-ASCII characters escaped (`revi\u{435}w`) with a warning, so a look-alike name can't pass for a real mode. Modes are listed builtin, then user, then project, at most 50 per source with the overflow counted per source, so project templates can't push builtins out. Harness-specific copies that differ (model, timeout, `harnesses:`, host check, …) are flagged with the differing fields named. `/delegate list` now shows the same data: per-harness tier, source (`builtin`/`user`/`project`) and warnings. A legacy-key warning that depends on the chosen harness (a native `permission:` overriding ignored `permissionMode:`/`sandbox:`) appears on the run, not in discovery.
- **`timeout:` template frontmatter** (whole seconds, 10–7200), plus a per-call `timeoutSec` tool parameter and a `/delegate --timeout=<sec>` flag (plain digits) with the same bounds. The configured timeout is template > per-harness `timeoutMs` > global `timeoutMs`; `/delegate --timeout=` replaces it, while the model-set tool `timeoutSec` can only lower it, so a prompt-injected model can't hold concurrency slots past your config. A timeout can never exceed 2 hours, and every transcript records the timeout the run got. An invalid template value is ignored with a `⚠` warning. An invalid per-call value is an error.
- **`harnesses:` template frontmatter**: the mode's default harness(es), used only when no harness is given. The `/delegate` command and the `delegate` tool treat it the same way. One name is a normal single run. Several names run as a normal fan-out with detection filtering, slot queueing, a single danger confirm covering every harness, the `addDirs` confirm, and resume rejection. `all` is not accepted. A mode kept only under another harness's template folder (e.g. `templates/codex/x.md` with `harnesses: codex`) uses that copy's `harnesses:` (rather than failing as an unknown mode on the default harness) — the default harness's own copy decides when it has one, copies are never mixed, and `delegate_modes` shows the same result. An untrusted project's templates can never choose the harness.
- **Template warnings share the discovery sanitizer's character set**: the `\uXXXX` escaping of values echoed in `⚠` template warnings now covers the same characters discovery strips, adding DEL, private-use characters, variation selectors, U+034F, the Hangul fillers, U+17B4/U+17B5 and the blank Braille pattern to what was escaped before.
